## 社長の判断が要ること

### 1. 開発者アカウントの名義

個人用アカウントの登録はすでに進んでいて、本人確認中です。このまま個人で進めるか、TackMore 名義に変えるかを決めてください。

| | 個人（Masaharu Sukekawa） | 組織（TackMore 株式会社） |
| --- | --- | --- |
| 想定の用途 | 学生、趣味、個人の開発者 | 商用、業務、行政など |
| 登録 | 登録済み | 新しく登録料 25 ドルが要る |
| D-U-N-S 番号 | 不要 | 必須。取得は無料。TackMore が持っているかは要確認 |
| 組織のウェブサイト | 不要 | 必要 |
| Play に公開される情報 | 法的氏名、国、メールアドレス。収益化しなければ住所は出ない | 法的名称、住所、メールアドレス、電話番号 |
| 12人14日のテスト | 必要 | 公式のページに記載なし。不要と書くのは第三者の記事だけ（要確認） |
| Spotify の拡張モード | 申請できない | 申請の条件のひとつ。ただし月間25万人以上も要る |
| ポリシーの運営者 | 今のまま | TackMore に書き換える |

推奨は個人のまま進めることです。登録が済んでいて、D-U-N-S 番号の取得を待たずに内部テストへ進めます。事業として売る段階になったら、アプリを組織のアカウントへ移せます。移すと利用者と評価は移りますが、テストのグループは作り直しです。

### 2. 一般公開で Spotify の音楽機能をどうするか（[#37](https://github.com/jphacks/sp_2608/issues/37)）

Spotify の開発モードは5人までで、拡張モードは法人で月間25万人以上の利用者が条件です。今のままでは一般の人は音楽機能を使えません。

| 案 | 内容 | 影響 |
| --- | --- | --- |
| A（推奨） | 製品版から音楽機能を外し、テストでは残す | 説明文の段落、マイクとメディア再生の申告、マイクの開示、Gemini の問題がなくなる。特徴の2と3は製品版に出ない |
| B | 残して「招待した人だけ」と説明に書く | 申告はすべて要る。5人しか使えない機能が審査の対象になる。EP-1 のおそれがある |
| C | Spotify 以外の音楽サービスに替える | 実装の作り直しになる |

### 3. Gemini とプレイリストの扱い

音楽機能を残すなら決めます。案 A なら不要です。

- Spotify の開発者ポリシーは、AI モデルへの利用や別のサービスへの受け渡しを制限しています。プレイリストの曲名とアーティスト名を Gemini へ送ることが当たるかは、規約の読み方の問題で、私たちだけでは判断できません。
- 今のキーが無料枠なら、入力は Google の製品改善に使われます。有料枠に変えるかを決めます。

### 4. マイクの判定と `GuestRequestService`

音楽機能を残すなら決めます。

- マイク：Play の用途の例は音声コマンドと録音で、会話の量の判定は例にありません。審査で通らなければ、この機能を外す前提でよいかを決めます。
- `GuestRequestService`：自分で音を出さないので、メディア再生の種類に合わないおそれがあります。推奨は、受け付けを案内中だけにして、`NavigationService` の動作に任せることです。案内していないときの受け付けはなくなります。

### 5. 配布する国

推奨は日本だけです。対象の地域が北海道なので、ほかの国に出す理由がありません。日本だけだと、審査のために模擬 GPS での確認が要ります。審査の担当者への説明は下書き済みです。

### 6. 公開するメールアドレス

Play にはデベロッパーのメールアドレスが公開されます。今のプライバシーポリシーは個人の Gmail です。問い合わせ用のアドレスを分けるかを決めてください。変えるならポリシーも直して上げ直します。

### 7. Cloud Run を常に起動しておくか

今は `minScale: 0` で、使わないと止まります。品質ガイドラインの DR-3 は読み込み10秒以内です。

2026-10 の Cloud Run の記録では、止まった状態からの最初の応答に、検索で7〜8秒、景観ルートの依頼で15.8秒かかっていました。景観ルートは10秒を超えます。

10月21日に出た「経路サーバーへ接続できません」は、この起動待ちが原因でした。アプリが15秒で通信を打ち切っていたためです。アプリ側は待つ時間を30秒に延ばしました。それでも最初の検索は待たされるので、`minScale: 1` にするかを決めてください。常時起動の分、費用が増えます。

### 8. アプリに入れるトークン

`ROUTING_TOKEN` と `MEMORY_WEB_TOKEN` は AAB の manifest に入ります。AAB や APK を手に入れた人は読み取れます。テストの間はこのままでよいです。一般公開の前に、サーバー側の回数制限と費用の上限の通知を入れるかを決めてください。

DD-1 について：窓の機器の換気の知らせは、案内用の音声の経路（`USAGE_ASSISTANCE_NAVIGATION_GUIDANCE`）で読み上げています。コードのコメントによると、ほかの用途にすると鳴らない車載機があったためです。DD-1 を守るには、用途を替えるか、車の画面に出している間は読み上げないかのどちらかです。どちらにするかは、実車で鳴り方を確かめてから決めます。

### 10. 掲載画像

Play のアイコンはランチャーのアイコンと揃える決まりです。`design/store/icon-512.png` は朝焼けの写真にロゴの「旅」の字を重ねました。これを採用するなら、ランチャーのアイコンも同じ絵に替えます。今の太陽と道のアイコンを残すなら、Play にもそれを上げます。

掲載画像の写真は、公開の前に次の2点を確かめてください。

- **使う権利:** 朝焼けの写真はチームのステッカーのもので、撮った人の了解を取りました（2026-11-03）。道の写真は、ネットで見つけた3枚を写真ACの北海道の写真3枚に差し替えました（2026-11-03、出所は[掲載情報](store-listing.md#スクリーンショット)）。
- **撮影地:** 旅れこの対象は北海道です。北海道ではない写真を使うと、案内できない場所を見せることになり、品質ガイドラインの EP-1（掲載のとおりに動く）に当たるおそれがあります。

道の写真を写真ACに替え、朝焼けの写真の了解も取れたので、掲載画像をコミットしました（2026-11-03）。写真ACの元の写真は、規約で写真そのものの配布が禁止されているので、リポジトリに入れません。

フィーチャーグラフィックとスクリーンショットには、calimoto や Roadtrippers と同じくスマホの絵を入れました。Play の案内は端末の絵を避けるよう書いているので、おすすめ枠の対象外になることがあります。

ブランチの順番にも判断が要ります。`feat/cloud-run` は今の積み重ねに入っていません。push と PR は指示があるまで行いません。
