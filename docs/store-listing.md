## 短い説明

```text

```

## 詳しい説明

`【Spotify の判断待ち】` の段落は、Spotify の扱いが決まるまで確定できません。一般の人が使えない機能を載せると、品質ガイドラインの EP-1（掲載のとおりに動く）に当たるおそれがあります。音楽機能を外して公開するなら、この段落を消します。

```text
旅れこは、移動そのものを楽しむためのドライブナビです。

最短の道ではなく、走って気持ちいい道を探します。寄り道してよい時間と好みの景色を選ぶと、海・森・湖・川などの景色を長く楽しめる道を、雰囲気の違う最大6案で提案します。

対象の地域は北海道です。ほかの地域では経路を検索できません。

■ 景色で道を選ぶ
・海沿い、森林、自然を楽しむ、湖・川、渓谷、田園、市街地から好みの景色を選べます
・寄り道してよい時間は、最大6時間まで決められます
・候補ごとに時間、距離、景色、通る名道を比べられます
・目的地を決めない周遊では、出発地へ戻るドライブルートを提案します
・天気や太陽の位置も評価に使います

■ 車の画面で案内する
・Android Auto に対応しています
・スマートフォンで選んだルートを、車の画面の地図と曲がり角の案内で走れます
・ルートの線は、景色ごとの色で塗り分けます

■ 走った道をステッカーに
・目的地に着くと、走った記録が残ります
・写真を水彩、ポスター風、フィルムカメラ風に加工し、走った道の形、地名、メンバーを入れたステッカーを作れます
・ネットワークプリントを使って、コンビニで印刷できます
・ステッカーの QR コードから、走った経路と写真のページを開けます。このページは、URL を知っている人なら誰でも見られます

【Spotify の判断待ち】
■ 景色と車内に合う音楽
・Spotify Premium のアカウントと連携すると、走っている道の景色と車内の会話の量に合わせて曲を選びます
・同乗者は QR コードから、ログインなしで聴きたい曲をリクエストできます
・マイクの音は端末の中で会話の量を判定するだけで、録音も送信もしません

■ ご利用にあたって
・Android 8.0 以上で使えます。車の画面で使うには、Android Auto に対応した車かディスプレイオーディオが必要です
・リアルタイムの通行止め、交通規制、渋滞の情報は反映していません。現地の標識と状況に従ってください
・運転中は操作しないでください。目的地の設定は停車中に行ってください
・景色の評価は公開データからの推定で、眺望を保証するものではありません
```

## スクリーンショット

5枚を作りました。Claude Design のキャンバスで直せます。書き出したものは `design/store/screenshots/` にあります。キャンバスの共有は社長だけに戻しました。写真ACの写真に替えた版は、元の写真をキャンバスに上げず、手元で組み立てて書き出しました。Play のおすすめ枠の条件に合わせ、すべて 1080 × 1920 の24ビット PNG です。見出しは画像の高さの20%以内です。

| 順番 | ファイル | 見出し | 代替テキスト |
| --- | --- | --- | --- |
| 1 | `01-scenery.png` | 走って気持ちいい道を、探そう。 | 景色のチップが並ぶ地図の画面 |
| 2 | `02-compare.png` | 雰囲気の違うルートを、並べて比べる | 景色の違うルートの候補を比べる画面 |
| 3 | `03-preferences.png` | 好みの景色を、細かく決める | 海や森などの好みを調整する画面 |
| 4 | `04-guidance.png` | 地図で確かめて、案内を開始 | 候補のルートを地図で確かめる画面 |
| 5 | `05-sticker.png` | 走った道を、ステッカーに | 朝焼けの写真に走った道を重ねたステッカー |

作るときに決めたことです。

- スマホの画面は、2026-10-19 の PV の実際の画面です。公開までに画面が変わったら、撮り直して差し替えます。
- スマホの枠は Android Studio の Pixel 9 の公式の枠です。
- 音楽機能を外して公開するなら、画面の下の「Spotify と連携して音楽を流す」の帯が写らないように撮り直します。
- ステッカーの同乗者の名前は架空のものに替え、QR コードは外しました。
- 背景の切り抜きとトップ画像には、写真ACの北海道の道の写真3枚を使っています（下の表）。
- 車の画面の素材がないので、車の画面は入れていません。撮るときは DHU の画面を 16:9 で撮ります。

道の写真の出所です。

| 写真 | 撮影地（写真ACの題名とタグによる） | 写真ACの番号 | 投稿者 |

| 紅葉の森の道の空撮 | 阿寒横断道路 | [35463264](https://www.photo-ac.com/main/detail/35463264) | makieni |

写真ACの規約（2026-11-03 に確認）では、制作物の一部として使うことは商用でも自由で、クレジットは要りません。写真そのものを公開・配布することは禁止です。そのため、元の写真はリポジトリにもキャンバスにも置かず、書き出した画像だけを残します。

撮り直すときの手順です。

```sh
adb shell wm size 1080x1920
adb emu geo fix 140.7264 41.7737
adb exec-out screencap -p > screen.png
adb shell wm size reset
```

自宅の近くや実在の人の写真が写らないようにします。地図の出典の表示は消しません。

## コンテンツレーティングの回答案

カテゴリは「その他のアプリ」を選びます。設問の文面は公開されていないので、Console の文面を見て確かめます（要確認）。年齢区分は回答のあとに決まります。

| 設問の内容 | 回答案 | 理由 |
| --- | --- | --- |
| 暴力、性的な表現、不適切な言葉、薬物、ギャンブル | いいえ | 該当する内容がない |
| 利用者同士のやりとり | はい | 同乗者が呼び名と曲を送れる。思い出のページで写真を見せられる。音楽機能を外しても、ページの共有は残る |
| 現在地を他の利用者に共有する | いいえ | ページに載るのは走り終えた道のりで、今いる場所ではない |
| アプリ内の購入 | いいえ | 課金がない |
| ウェブブラウザの機能 | いいえ | アプリにブラウザの機能はない。Spotify のログインは外部の画面で開く |

## フォアグラウンドサービスの申告と動画

Play Console の App content で、種類ごとに次の内容を入れます。動画は実機の画面録画で、1本30秒から1分を目安にします。置き場所の指定は Console の入力欄で確かめます（要確認）。YouTube の限定公開が使えるなら、それを使います。

共通の準備です。

1. Play から入れた版か、同じ接続先で作った Release 版を使います。
2. 録画は `adb shell screenrecord /sdcard/fgs.mp4` です（最大3分）。
3. 通知の領域を開いて、通知が見える場面を必ず入れます。
4. 個人の名前や自宅の場所が写らないようにします。現在地は模擬の位置で函館駅にします。

### 位置情報（`NavigationService`）

| 入力欄 | 内容 |
| --- | --- |
| 用途 | Background Location Updates の Navigation |
| 機能の説明 | 利用者が案内を始めると、画面を消したり車の画面だけで使ったりしている間も現在地を取り続け、曲がり角を案内する |
| 止められたときの影響 | 案内が途切れ、曲がり角を過ぎたり現在地がずれたりする |

撮影の手順です。

1. マップで目的地を検索し、ルートを選びます。
2. 「案内を開始」を押します。
3. 通知の領域を開き、「旅れこ ナビ」の通知を見せます。
4. ホームに戻り、通知の案内が更新されるのを見せます。
5. アプリに戻って案内を終え、通知が消えるのを見せます。

### マイク（`CabinListeningService`）

| 入力欄 | 内容 |
| --- | --- |
| 用途 | Background Audio Access。一覧の例と違うので、当てはまらなければ自分で入力する |
| 機能の説明 | 利用者が景観 BGM を始めると、車内で会話しているかを端末の中で判定し、選曲に使う。音声は録音も送信もしない |
| 止められたときの影響 | 判定が止まり、車内の様子を「ふつう」として選曲する |

撮影の手順です。Spotify と連携し、マイクを未許可にしておきます。

1. 設定から「Spotify 連携」を開きます。
2. 「景観BGMを始める」を押します。
3. OS のマイクの許可ダイアログで許可します。
4. 通知の領域を開き、「旅れこ 景観BGM」の通知の「会話の量だけを端末内で判定しています。音声は保存・送信しません。」を見せます。
5. ホームに戻り、通知が残っているのを見せます。
6. アプリに戻って「景観BGMを終了」を押し、通知が消えるのを見せます。

目立つ開示の画面を足したら、手順の3の前に入れます。

### メディアの再生（`GuestRequestService`）

このサービスは自分では音を出しません。今の形のまま申告すると、用途と合わないと判断されるおそれがあります。[チェックリスト](play-release-checklist.md#社長の判断が要ること)の判断のあとで撮ります。

| 入力欄 | 内容 |
| --- | --- |
| 用途 | Media Playback |
| 機能の説明 | 利用者が曲のリクエストの受け付けを始めると、画面を閉じても同乗者の曲を受け取り、車内で続けて再生する |
| 止められたときの影響 | リクエストが届かなくなり、予約した曲が再生されなくなる |

撮影の手順です。Spotify と連携し、再生先を選んでおきます。同乗者役の端末を1台使います。

1. 設定から「Spotify 連携」を開きます。
2. 「みんなのリクエスト」の「QR コードで受け付ける」を押します。
3. 通知の領域を開き、「旅れこ リクエスト受付中」の通知を見せます。
4. もう1台で QR コードを読み取り、曲をリクエストします。
5. ホームに戻り、曲が再生されるのを見せます。
6. 通知の「受付終了」を押し、通知が消えるのを見せます。
