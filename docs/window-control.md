# 窓の操作

助手席の窓を Android アプリから開閉します。車側の機器は `hardware/window-ai`(ステップワゴン RG2 の
助手席パワーウィンドウを ESP32 と BME688 で制御する一式)で、[配線](../hardware/window-ai/docs/wiring.md)と
[開発手順](../hardware/window-ai/docs/ota-guide.md)はそちらを参照してください。

純正スイッチの配線は生かしたままです。車載リレーが OFF のとき `30-87a` がつながるので、アプリや ESP32 が
停止していても運転席・助手席のスイッチで従来どおり開閉できます。

## 責務

| 所有モジュール | 契約・実装 | 責務 |
| --- | --- | --- |
| feature/cabin | `WindowGateway` | 窓を動かす指示と、機器の接続状態・車内の空気の配信 |
| feature/cabin | `CabinAir` | ガス抵抗・普段比・湿度・暖機状態の読み取り値 |
| platform/android-window | `BleWindowGateway` | 機器の探索、BLE 接続、コマンド送信、ログ受信 |
| platform/android-window | `BleLines` | notify の断片を改行で区切られた行へ組み立て直す |
| platform/android-window | `Esp32Log` | 1行の測定値を `CabinAir` へ読み取る |
| platform/android-window | `WindowConfiguration` | 機器の名前と BLE の UUID |
| platform/android-window | `WindowPermissions` | BLE に必要な許可の一覧と判定 |
| platform/android-window | `AndroidWindowRuntime` | 接続を1つ所有。Activity の再生成をまたぐ |
| platform/android-window | `WindowActivity` / `WindowScreen` | 専用画面 |

`WindowGateway` は通信方式を含みません。機器との接続方法を変えても、契約と画面は変わりません。
`feature/cabin` の `CabinPolicy` が出す提案（海が近い、雨が吹き込む）とは独立していて、
提案から自動で窓を動かす接続はしていません。

## 接続

**BLE でつなぎます。** 機器は 1 文字のコマンドを受け取り、測定値とログを 1 行ずつ返します。
アプリは接続を 1 本張り続け、切れたら 3 秒ごとに探し直します。

| 口 | UUID | 向き |
| --- | --- | --- |
| サービス | `6e6b1f00-5f3a-4b7c-9d21-8c4f1a2b3c01` | 機器が広告に載せる |
| コマンド | `6e6b1f01-5f3a-4b7c-9d21-8c4f1a2b3c01` | アプリ → 機器（write） |
| ログ | `6e6b1f02-5f3a-4b7c-9d21-8c4f1a2b3c01` | 機器 → アプリ（notify） |

| 送る文字 | 画面の操作 | 機器の動作 |
| --- | --- | --- |
| `d` | 開ける | 窓を下げる 0.5 秒 |
| `u` | 閉める | 窓を上げる 0.5 秒 |
| `s` | 停止 | 動作中のリレーを切る |
| `i` | （画面には無い） | 機器の状態を返す |
| `o` | （画面には無い） | Wi-Fi と OTA を 5 分だけ立てる |

1 回の操作で動くのは 0.5 秒です。全開・全閉にするには繰り返し押します。機器側で 4 秒の上限を持ち、
上げと下げを同時に ON にしません。

接続先はサービス UUID で見つけるので、アドレスの事前設定は要りません。機器の名前は広告の 31 バイトに
収まらないため走査応答へ回してあり、拾えないこともあります。拾えたときだけ `stepwgn-window` と照合します。

notify で一度に運べるのは MTU-3 バイトなので、1 行が途中で切れて届きます。逆に 1 回の notify へ
複数行が入ることもあります。`BleLines` が改行まで生のバイトで溜めてから文字へ直すので、日本語が
断片の境界で分かれても壊れません。MTU は 185 を要求しますが、広げられなくても動きます。

BLEで窓機器へ接続し、端末のWi-Fiは地図・音楽・API通信に利用できます。接続先アドレスのビルド時設定は不要です。

## 許可

窓の画面を開くと BLE の許可を求めます。地図や音楽には関係しません。

| Android の版 | 求める許可 |
| --- | --- |
| 12 以上 | `BLUETOOTH_SCAN`（`neverForLocation` 付き）と `BLUETOOTH_CONNECT` |
| 11 以下 | `ACCESS_FINE_LOCATION`（この版は BLE の探索に位置情報の許可が要る） |

`BLUETOOTH_SCAN` には `neverForLocation` を付けているので、12 以上では位置情報を求めません。
許可が無いあいだ、Bluetooth が切られているあいだは画面は操作を受け付けません。

## 画面

ホームの「窓を操作」から開きます。接続先と接続状態、開ける・閉める・停止、車内の空気、機器のログを
表示します。ログは機器が送る診断用の文字列をそのまま並べたもので、最新の 60 行を保持します。

車内の空気は `ガス 204.4kΩ 普段比 -0% 湿度 32.0%` の形式の行から作ります。普段比は機器が保持する
基準値からの低下率で、大きいほどにおいが強いことを示します。起動から 5 分は `暖機中` で、機器は
においの検知をしません。ガスセンサーは揮発性有機化合物にまとめて反応するので、
においの種類を区別しません。コーヒーや息にも反応します。

## 実装状況

| 項目 | 状況 |
| --- | --- |
| アプリからの開閉・停止 | 実装 |
| BLE での接続・自動再接続・接続状態の表示 | 実装 |
| 車内の空気の表示・機器のログ表示 | 実装 |
| OTA のオンデマンド起動（`o`） | 実装（機器側）。アプリの画面からは送れない |
| においによる自動開放 | **機器側のみ**。アプリは窓を動かさず、知らせるだけ |
| 検知したときの音声お知らせ | 実装。端末内蔵の TTS で読み上げる |
| 検知したときの Android Auto の表示 | 実装。`Alert`。出せないときは `CarToast` に落ちる |
| 検知したときのスマホの表示 | 実装。ダッシュボード下部のシート。6秒で消える |
| `CabinPolicy` の提案から窓を動かす | 未実装 |
| 窓の現在位置（開度）の取得 | 未実装。機器に位置センサーがない |
| 操作の結果確認 | 未実装。コマンドの送信成功までしか分からない |
| Android Auto からの操作 | 未実装 |
| iOS | 未実装。BLE なので実装は可能（SPP と違い MFi が要らない） |
| しきい値・動作時間のアプリからの変更 | 未実装。機器側の定数 |

機器は検知したとき、人が読む `におい検知 → 窓を少し開ける` と、機械が読む `EVENT smell drop=42` の
2 行を出します。アプリが見るのは後者だけです。前者は表示用なので、文言を変えても検知は壊れません。

## 換気の知らせ

機器がにおいを検知して窓を開けると、アプリが3つの経路で知らせます。

| 所有モジュール | 契約・実装 | 責務 |
| --- | --- | --- |
| feature/cabin | `CabinNotice` / `CabinNotices` | 知らせの中身と文面 |
| feature/cabin | `CabinNoticeSource` / `CabinNoticeOwner` | 知らせの配信元の契約 |
| platform/android-window | `BleWindowGateway` | `EVENT smell` 行から知らせを作って流す |
| platform/android-window | `CabinNoticeSpeaker` | TTSと一時的な音声フォーカスによる読み上げ |
| androidApp | `TheaCarApplication` | 通知配信元と読み上げの接続 |
| platform/android-auto | `TheaCarSession` | 車載画面の `Alert` |
| feature/dashboard | `CabinNoticeSheet` | スマホ画面のシート |

通知は「空気を入れ替えますね」「窓を少し開けました」とし、においの検知には触れません。

読み上げはpitch 0.95 / rate 0.9。音声用途はナビ案内とし、`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`で一時的にフォーカスを取得します。Spotifyの音量低下はOSに任せます。

TTSの初期化・音声フォーカス取得に失敗した場合は読み上げません。

- **車載画面の `Alert` は `NavigationTemplate` が出ている間だけ**表示されます。案内していないとき
  （`PaneTemplate`）や、利用者が別のアプリを見ているときは出ないので、`CarToast` に落とします
- **スマホのシートはダッシュボードを見ているときだけ**表示されます

連続した検知の抑制は機器側のクールダウン（60秒）に任せています。アプリ側では抑制しません。
知らせは一度きりの出来事なので状態として保持せず、受け取り手がいなければ捨てます。

サービスUUIDや機器名による照合は暗号的な認証ではありません。周囲からの操作を拒否できる保証はなく、限定した開発環境で使用します。

**送信が成功しても窓が動いたことの確認にはなりません。** 機器がコマンドを受け取ったところまでしか
分かりません。モーターの押し付け、保護装置の作動、挟み込みは検知できないので、画面を見ながら
操作してください。安全のため、アプリから自動で窓を閉める処理は入れていません。

機器の電源は IG 電源（キー ON のときだけ 12V）から取っています。キーを抜くと機器は停止し、
アプリの接続も切れます。

## ファームウェアの更新

起動時に Wi-Fi は上げません。更新したいときだけ `o` を送ると、機器が 5 分だけ Wi-Fi と OTA を立て、
時間が来ると自分で切ります。手順は [ota-guide](../hardware/window-ai/docs/ota-guide.md) にあります。

`o` を送る口はアプリの画面にはありません。USB のシリアル、または nRF Connect のような汎用の BLE
アプリからコマンドの口へ `6f` を書いて送ります。

**パーティションの設定を変えたときは OTA では更新できません。** `car_v3_ble` は
`Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)` でビルドする前提で、既定の設定だと入りません。
v2 から v3 への更新は一度だけ USB で書き込みます。以降の v3 同士の更新は OTA でできます。

## 検証

```shell
./gradlew -g .gradle-local verifyModuleBoundaries \
  :platform:android-window:testDebugUnitTest :androidApp:assembleDebug :androidApp:lintDebug
```

テストは行の組み立て直し（`BleLines`）、ログの解析（`Esp32Log`）、BLE の UUID と名前の照合
（`WindowConfiguration`）だけです。実機の通信、窓の動作、安全性の試験ではありません。

機器だけを先に確かめるときは、nRF Connect のような汎用の BLE アプリが使えます。
`i`（`69`）は情報を返すだけでリレーを動かさないので、送信の経路を無害に確かめられます。

実車での確認は停車中に行い、窓の開口部に手や物がないことを目視してから操作してください。
