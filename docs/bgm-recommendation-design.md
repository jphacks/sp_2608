# 音楽推薦の設計

BGMサービス（bgm-api）が、次に流す1曲をどう決めているかをまとめます。再生の操作・設定・Spotifyとの連携は[景観BGMの推薦](bgm-recommendation.md)、APIの仕様は[bgm-api の API](../infra/bgm-api/docs/API.md)を参照してください。

推論は次の3段階です。

1. これから通る区間の景観を先読みし、数値にする
2. その数値を「欲しい曲調」（6軸の目標）に変換する
3. 楽曲DBの曲を目標と比べて採点し、上位から1曲を抽選する

入力は、走行中のルートと現在位置、今流れている曲の長さ、時刻、車内の状態、同乗者のプレイリスト、再生履歴です。景観から曲調への変換は固定の係数を使うルールベースで、学習したモデルは使っていません。

## 次の曲が流れる区間を先読みする

曲は3〜4分続くので、今いる場所の景色だけを見て選ぶと、曲の後半には別の景色になっていることがあります。そこで「この曲が終わるまでに、どこまで進むか」を見積もり、その区間全体の景観をまとめて評価します。

![経路進捗と曲長から先読みし、景観の占有率と信頼度へ変換する流れ](media/bgm-recommendation/02-scenic-window.png)

進む距離は、到着予測時刻から求めた速度と曲の長さで決めます。

```text
先読み距離[km] = 予測速度[km/h] × 曲長の目安[秒] / 3600
```

次に流す曲はまだ決まっていないので、曲長には今流れている曲の長さを目安として使います。曲長が分からなければ210秒、速度が推定できなければ40km/hとし、その場合は約2.33km先までが対象です。

この区間に重なる景観を長さで集計し、景観ごとに「強さ `v`」と「信頼度 `q`」を出します。

```text
v = その景観の区間長 / 評価済み区間長
q = カテゴリの信頼度 × 評価済み割合
評価済み割合 = 評価済み区間長 / 窓と重なる全ブロック長
```

評価済みの2kmのうち海が1.2km、森林が0.8kmなら、海は0.6、森林は0.4です。データの無い区間（`unknown`）は分母から外し、その分だけ信頼度を下げます。景観が分からない区間が多いときに、少ない情報で曲調を大きく振らないためです。

景観の元データは、OpenStreetMapの道路周辺にある海岸線・森林・水域などです。景観タイムラインのカテゴリは、音楽側では次の特徴として扱います。

| タイムライン | 音楽側の特徴 |
| --- | --- |
| `sea` | 海の近さ `sea_proximity` |
| `sea` のうち眺望を確認できた区間 | 海の眺望 `sea_visibility` |
| `forest` | 森林 `forest` |
| `open_nature` | 自然 `nature` |
| 湖・川・谷・内水面 | 水辺 `water`（まとめて集計） |
| `farmland` | 田園 `rural` |
| `townscape`・`urban` | 市街地 `urban` |
| 開放度 | `openness`（距離で重み付けした平均） |

海が近いことと、海が実際に見えることは別に扱っています。海岸線から近くても、防風林や建物で海が見えない道は多いからです。

## 景観を「欲しい曲調」に変換する

曲調は次の6軸で表します。どの軸も0〜1の値です。

| 軸 | 0に近い | 1に近い |
| --- | --- | --- |
| `energy` | 静か | 激しい・高揚感がある |
| `valence` | 切ない・暗い | 明るい |
| `tempo` | 遅い | 速い |
| `acoustic` | 電子音・打ち込み | 生楽器中心 |
| `spacious` | 密な音像 | 余白・広がりがある |
| `vocal` | インスト | ボーカルが前面に出る |

全軸を0.5から始め、景観の強さと信頼度に比例して係数を足します。

```text
目標 T[a] = 0.5 + Σ（強さ v[f] × 信頼度 q[f] × 係数 E[f,a]）
```

| 景観 | energy | valence | tempo | acoustic | spacious | vocal |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 海の近さ | +0.10 | +0.20 | +0.05 | 0 | +0.15 | 0 |
| 海の眺望 | +0.10 | +0.10 | 0 | 0 | +0.15 | 0 |
| 開放度 | 0 | +0.05 | 0 | 0 | +0.25 | 0 |
| 森林 | −0.10 | 0 | −0.05 | +0.25 | −0.05 | −0.05 |
| 自然 | −0.05 | 0 | 0 | +0.15 | +0.05 | 0 |
| 田園 | 0 | +0.10 | −0.05 | +0.10 | +0.05 | 0 |
| 市街地 | +0.10 | 0 | +0.05 | −0.15 | −0.20 | 0 |
| 水辺 | −0.10 | 0 | −0.05 | +0.05 | +0.20 | −0.05 |

海沿いでは明るく広がりのある曲、森の中では落ち着いた生楽器寄りの曲、街中では密度のある速めの曲、という方向にしています。この係数は私たちが決めた初期値で、学習したものではありません。[engine.ts](../infra/bgm-api/src/engine.ts) の定数にまとめてあり、走行テストとユーザー評価を見ながら調整する予定です。

### 時間帯・車内・運転の状況で補正する

景色が同じでも、夜と昼、会話が弾んでいるときと全員が眠そうなときでは、合う曲が違います。景観から作った目標に、次の補正を加えます。

| 状況 | 補正 |
| --- | --- |
| 夜（19時から翌4時まで） | energy −0.10 |
| 朝（4時から9時まで） | tempo +0.05 |
| 名道を走っている | energy +0.10。知名度・共有の加点を2.5倍 |
| 会話が盛り上がっている | vocal −0.20（話し声と歌声がぶつからないように） |
| 車内が静か | valence +0.05。知名度・共有の加点を2.5倍 |
| 休息中（長時間運転で静か） | energy −0.20、tempo −0.10、vocal −0.20、energyの上限0.40 |
| 運転負荷が高い | energyの上限0.60、vocalの緩い上限0.50 |
| カーブが続く | energyの上限0.65、vocalの緩い上限0.60 |

車内の状態は、スマホのマイクで「誰かが話しているか」だけを端末内で判定して決めます。音声そのものは保存も送信もしません。

最後に、前回の目標から各軸±0.25以上は動かないように抑えます。景色が切り替わる地点でも、曲調が急に飛ばないようにするためです。

## 候補曲と比べて選ぶ

![景観から目標6軸を作り、楽曲の順位との距離と加減点で採点して抽選する流れ](media/bgm-recommendation/03-target-scoring.png)

### 楽曲DB

比べる相手は、自前の楽曲DBにある曲です。現在のカタログは邦楽・洋楽・インスト・K-POPの2,057曲で、Geminiが曲名とアーティスト名から6軸・知名度・タグ・推定の信頼度を付けています。同乗者のプレイリストを取り込んだときは、カタログに無い曲だけを同じ方法で注釈してDBに追加します。

### 値そのものではなく、候補内の順位で比べる

各曲の6軸は、そのままの値ではなく、候補集合の中での順位（0〜1）に直してから目標と比べます。目標の0.7は「値が0.7の曲」ではなく、「候補の中で上から3割くらいの曲」という意味になります。

こうしているのは、候補集合が場面によって大きく変わるからです。カタログ全体から選ぶときと、1人のプレイリストの中だけから選ぶときでは、曲調の分布がまったく違います。順位にしておけば、どちらの場合でも、同じ目標で「その中で一番明るめの曲」を選べます。

```text
距離 D = √（Σ w[a] × (T[a] − R[a])² / Σ w[a]）
```

重み `w` は基本的に1で、tempoだけ0.5です。景観がはっきりしている（最も強い景観の `v×q` が0.3以上の）ときは、その景観で大きく動かした上位2軸の重みを1.5にし、海なら明るさと広がりを特に重視します。候補内で値の幅が0.2未満しかない軸は、わずかな差で順位が大きく変わるのを避けるため、重みを下げます。

### 加点と減点

距離だけで選ぶと、知らない曲が続いたり、同じアーティストが連続したりします。そこで距離に加減点をします。

```text
score = −距離
        − 0.30 × 過去のドライブで流した曲
        − 0.15 × 直近3曲と同じアーティスト
        − 所有者係数 × 1人のプレイリストへの偏り
        + 共有係数 × 複数人が持っている度合い
        + 知名度係数 × 知名度
        + プレイリスト内・同じアーティストの加点
        − 0.20 × 注釈の信頼度不足
        − 上限の超過量
```

今回のドライブで流した曲は、採点する前に候補から外します。係数はモードによって変えています。

| モード | 候補 | 知名度 | 共有 | 偏りの減点 | 好みの加点 |
| --- | --- | ---: | ---: | ---: | --- |
| `discover` | カタログ全曲 | 0.05 | 0 | 0 | なし |
| `blend`（既定） | カタログ全曲 | 0.10 | 0.10 | 0.40 | リスト内 +0.10、同じアーティスト +0.04 |
| `playlist` | 同乗者のリスト内 | 0 | 0.10 | 0.40 | なし |

Androidの「好み＋新しい曲との出会い」は `blend`、「プレイリスト内だけ」は `playlist` です。偏りの減点は、直近10曲のうち1人のリストの曲が均等な割合を超えた分にかかります。誰か1人の好みばかりが続かないようにするためです。

### 最高点の曲に決め打ちしない

最後は、最高点から0.1以内に入った曲（最大30曲）から、点数に応じた確率で1曲を選びます。

```text
重み z[i] = exp((score[i] − 最高score) / 0.06)
選曲確率 P[i] = z[i] / Σ z[j]
```

毎回最高点の曲を選ぶと、同じルートを走るたびに同じ曲順になってしまいます。点数の近い曲にも機会を残すことで、選曲に幅を持たせています。同じ入力と同じ `seed` を渡せば、結果は再現できます。

目標に近い曲がどれも遠い（最小距離が0.35を超える）ときは、直前に流した曲の曲調を基準に選び直します。景色に合う曲が無いときに、無理に合わせて雰囲気を壊すよりは、今の流れを保つほうが自然だと考えたためです。

## 例：海沿いの区間

海の近さ0.9、海の眺望0.8（信頼度0.7）、開放度0.8の区間を、昼の14時に通る場合です。車内は通常で、名道・運転負荷・前回の目標による補正は無しとします。

```text
energy   = 0.5 + 0.9×0.10 + 0.8×0.7×0.10              = 0.646
spacious = 0.5 + 0.9×0.15 + 0.8×0.7×0.15 + 0.8×0.25   = 0.919
```

目標はenergy 0.65、valence 0.78、tempo 0.55、acoustic 0.50、spacious 0.92、vocal 0.50で、重みはvalenceとspaciousが1.5です。「明るく、広がりがあって、候補の中ではやや速めの曲」という指定になります。

[38曲の検証用プール](../infra/bgm-api/test/fixtures/tracks.json)で実際に計算した上位5曲です（`blend`、所有者なし、履歴なし、`seed=1`）。

| 順位 | 曲 | 距離 | 選曲確率 |
| --- | --- | ---: | ---: |
| 1 | 幾億光年 / Omoinotake | 0.216 | 17.6% |
| 2 | きらり / 藤井 風 | 0.216 | 17.5% |
| 3 | タイムパラドックス / Vaundy | 0.220 | 16.6% |
| 4 | マリーゴールド / あいみょん | 0.226 | 15.0% |
| 5 | Plastic Love / 竹内まりや | 0.243 | 11.2% |

抽選の対象は9曲で、`seed=1` では4位の「マリーゴールド」が選ばれました。

## 例：自然の多い区間で、車内が静かなとき

自然0.9の区間を、会話が途切れて静かになった車内で走る場合です。自然に合わせて激しさを抑え、生楽器寄りにします。さらに、静かな車内では知名度の加点を2.5倍にして、みんなが知っている曲を流れやすくします。

```text
energy   = 0.5 − 0.9×0.05 = 0.455
acoustic = 0.5 + 0.9×0.15 = 0.635
score    = −距離 + 0.10 × 2.5 × 知名度
```

現行カタログ2,057曲で計算した上位5曲です（`blend`、所有者なし、履歴なし、`seed=1`）。

| 順位 | 曲 | 距離 | 知名度 | score | 選曲確率 |
| --- | --- | ---: | ---: | ---: | ---: |
| 1 | 真珠のピアス / 松任谷由実 | 0.039 | 0.763 | +0.152 | 9.8% |
| 2 | プラスティック・ラブ / 竹内まりや | 0.091 | 0.878 | +0.129 | 6.6% |
| 3 | W / X / Y / Tani Yuuki | 0.081 | 0.808 | +0.121 | 5.8% |
| 4 | 4:00A.M. / 大貫妙子 | 0.095 | 0.814 | +0.108 | 4.7% |
| 5 | 喜劇 / 星野 源 | 0.114 | 0.886 | +0.108 | 4.7% |

2位の「プラスティック・ラブ」は、距離では3位の「W / X / Y」より遠いものの、知名度の加点で上回っています。抽選の対象は30曲で、`seed=1` では表に無い「春泥棒 / ヨルシカ」（選曲確率2.9%）が選ばれました。
