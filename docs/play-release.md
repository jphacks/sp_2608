# Google Play への配布

旅れこを Play Console の内部テストで配る手順です。Play から入れたアプリは、実車の Android Auto のアプリ一覧に出ます。サイドロードした APK は、DHU には出ても実車の一覧には出ません。

## 1. アップロード鍵を作る（初回だけ）

Play に上げる AAB は、手元のアップロード鍵で署名します。利用者に届くアプリの署名は Google が持つ鍵で行います（Play App Signing）。

鍵はリポジトリの外に作ります。パスワードは `keytool` が聞いてくるので、自分で決めて入力します。

```sh
keytool -genkeypair -v -keystore ~/keys/tabireco-upload.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

鍵ファイルとパスワードは、パスワード管理ツールなどに控えておきます。なくすと、Play Console からアップロード鍵の再設定を申請するまで更新を上げられません。

## 2. 鍵の場所を local.properties に書く

```properties
RELEASE_STORE_FILE=/Users/<ユーザー名>/keys/tabireco-upload.jks
RELEASE_STORE_PASSWORD=<鍵ストアのパスワード>
RELEASE_KEY_ALIAS=upload
RELEASE_KEY_PASSWORD=<鍵のパスワード>
```

`local.properties` と `*.jks` は `.gitignore` に入っています。4つのどれかが空のときは、Release ビルドは署名なしで作られ、Play には上げられません。

## 3. AAB を作る

経路 API などの接続先は、APK と同じく `local.properties` か Gradle プロパティから埋め込まれます。何も入れなくても `bundleRelease` は成功しますが、接続先が空のアプリになり、経路を検索できません。次の値を入れてから作ります。

| 名前 | 中身 |
| --- | --- |
| `VALHALLA_URL` | Cloud Run の経路 API の URL。`https://` で始まるもの |
| `ROUTING_TOKEN` | 経路 API のトークン |
| `MEMORY_WEB_URL` | 思い出のページのサイトの URL |
| `MEMORY_WEB_TOKEN` | 思い出のページのサイトのトークン |
| `SPOTIFY_CLIENT_ID` | Spotify のクライアント ID。音楽機能を入れるときだけ |

`GEOCODING_URL` は空のままで、経路サーバーの検索を使います。開発用の `http://10.0.2.2:8002` を入れて作らないでください。Release では平文の通信ができないため、つながりません。

```sh
./gradlew :androidApp:bundleRelease
```

JDK は Android Studio に同梱のものを使います。2026-11-02 の確認は次の指定で行いました。

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

`androidApp/build/outputs/bundle/release/androidApp-release.aab` ができます。上げる前に、埋め込まれた URL を確かめます。次のコマンドはトークンを表示しません。

```sh
grep -A1 -E 'com.theacar.(VALHALLA_URL|MEMORY_WEB_URL)' \
  androidApp/build/intermediates/merged_manifests/release/processReleaseManifest/AndroidManifest.xml
```

Play には、前に上げたものより大きい `versionCode` の AAB しか上げられません。2回目からは、上げる前に `androidApp/build.gradle.kts` の `versionCode` を1つ上げます。

## 4. Play Console で内部テストに上げる

1. Play Console でアプリを作ります。パッケージ名は `com.tabireco.app` です。最初の AAB を上げると決まり、あとから変えられません。
2. 内部テストのトラックにテスターのメールアドレスを登録し、AAB を上げてリリースします。内部テストは審査なしで配れます。
3. 詳細設定のフォームファクタで Android Auto を追加します。
4. テスター用のリンクから参加し、Play ストアから旅れこを入れます。サイドロードした旅れこは先にアンインストールします。署名が違うため、上書きでは入りません。

Release ビルドは公式の Android Auto 以外の接続元を拒否します（[車載での確認手順](android-auto-setup.md#42-debug-ビルドが必要な理由)）。

## 5. Play Console に出す申告

内容は[プライバシーポリシー](privacy-policy.md)と合わせます。ポリシーの URL は `https://tabireco-web.miraidai.workers.dev/privacy` です。

### データセーフティ

| データの種類 | 中身 | 収集 | 第三者との共有 | 任意か | 目的 |
| --- | --- | --- | --- | --- | --- |
| おおよその位置情報・正確な位置情報 | 経路の座標、走った道のり、撮影場所 | する | する（Open-Meteo） | 必須（経路の検索と案内に要る） | アプリの機能 |
| 氏名 | 同乗者の呼び名 | する | しない | 任意 | アプリの機能 |
| 写真 | 絵柄に加工した写真 | する | しない | 任意（ステッカーを作るときだけ） | アプリの機能 |
| デバイスなどの ID | インストールごとの識別子 | する | しない | 任意（旅の記録か音楽の記録を送るときだけ） | アプリの機能 |
| アプリのアクティビティ：アプリ内の検索履歴 | 目的地の検索に入力した文字 | する | しない | 任意（地図のタップでも選べる） | アプリの機能 |
| アプリのアクティビティ：その他のユーザー作成コンテンツ | 利用者が入力した地名 | する | しない | 任意 | アプリの機能 |
| アプリのアクティビティ：その他の操作 | 再生した曲、プレイリストの曲名とアーティスト名、会話の割合、車内のにぎやかさの段階 | する | Gemini の課金の状態による（下の説明） | 任意（Spotify と連携したときだけ） | アプリの機能 |
| 音声 | なし（端末の中で判定するだけ） | しない | しない | — | — |

Play の定義では、3平方キロメートル未満は「正確な位置情報」です。スマホから Open-Meteo へ送る約1km単位の座標はこれに当たります。

**再生した曲と会話の割合の推奨案**：「アプリのアクティビティ」の「その他の操作」で申告します。

- 再生した曲は、Play の定義の「ほかの項目に当てはまらないアプリ内の行動」に当たります。音源そのものは送らないので、「音声ファイル」には入れません。
- 会話の割合は音声から求めた数字で、録音ではありません。そのため「音声」にも入れません。ただし、マイクから得た情報なので、隠さず申告します。
- サーバーに残るので、「一時的な処理」にはしません。
- 旅の記録に添えて保存し、思い出のページに載せるので、目的は「アプリの機能」です。

**「共有」の扱いの推奨案**：Play は、運営者の指示で代わりに処理する事業者への受け渡しを「共有」に数えません。

- Cloud Run と Cloudflare は運営者のサーバーなので、「共有」に当たりません。
- Open-Meteo とは契約がなく、運営者の指示で処理する事業者とは言い切れません。少なく申告するほうが問題になるので、位置情報は「共有する」にします。OpenFreeMap も地図の範囲を受け取りますが、位置情報として申告するかは要確認です。
- Gemini は、無料枠だと入力が Google の製品改善に使われます。無料枠のままなら「その他の操作」を「共有する」にします。有料枠なら「共有しない」にします。今のキーの状態は要確認です。
- Spotify への送信は、利用者が連携を選んだ操作なので「共有」に当たりません。
- 思い出のページは、利用者が保存して URL を渡す操作なので「共有」に当たりません。

そのほかの回答です。

- 通信はすべて HTTPS で暗号化しています。
- 削除の依頼は、問い合わせ先のメールで受け付けます。ポリシーの「5. 削除の依頼」を案内します。
- 検索の文字は Cloud Run の通信の記録に残ることがあるので、「一時的な処理」にはしません。
- アカウントの質問は「作成できない」と答えます。Spotify の連携の扱いは要確認です。
- 同乗者の曲のリクエストは、アプリではなくブラウザのページから届くので、この表には入れていません。

### フォアグラウンドサービス

| サービス | 種類 | 用途 | 起動する操作 |
| --- | --- | --- | --- |
| `NavigationService` | 位置情報 | 画面を消したり車の画面だけで使ったりしている間も、現在地を取って曲がり角を案内する | 経路を選んで案内を始める |
| `CabinListeningService` | マイク | 案内中、車内で会話しているかを端末の中で判定し、音量と選曲を変える | Spotify と連携し、マイクを許可した状態で案内を始める |
| `GuestRequestService` | メディアの再生 | 同乗者がQRから送った曲を受け付け、車内で再生し続ける | Spotify と連携した状態で、曲のリクエストの受付（QR）を始める |

それぞれ、起動する操作の動画を撮って添えます。申告の文面と撮影の手順は[掲載情報](store-listing.md#フォアグラウンドサービスの申告と動画)にあります。
