# ドライブシミュレータ

ハンコン（ロジクールの G29）とペダルで、北海道の景色のよい道を走るシミュレータです。走った位置をスマホの旅れこ（Debug ビルド）へ現在地として送るので、ナビの案内が運転に合わせて進みます。JPHACKS Award Day（2026-11-15）の EXPO で、景色とナビを一緒に見せるために作りました。

- **景色:** Google ストリートビューの写真を自前で描きます。写真を「地面」と「周りの円筒（半径 80m）」という仮の形に貼り、カメラを連続して前へ動かすので、写真と写真の間も前へ進んで見えます。
  - 次の写真には、近づくにつれて、ゆっくり始まりゆっくり終わる形で重ねて替えます。
  - 次の写真を読み終えるまでは、入れ替えを始めません。
  - 交差点で横道の写真を拾わないよう、道の向きに沿って撮った写真だけを使います。
  - 4枚先（約70m、時速 60km で約4秒分）まで先読みし、車に近い写真から順に読み込みます。先の写真は、その地点の道の向きの分を読みます（カーブの先でずれないように）。
  - 2011 年ごろの古い写真（美瑛などに残っている）は大きさが小さく、タイルの並びが違うので、写真ごとに並びを合わせます。
- **車:** 制限速度は時速 60km、ブレーキは実車の約 3 倍効きます（体験会で止まりやすいように）。
- **道:** OSM の道路網の、道幅の中を自由に走ります。ハンドルで車の向きが変わり、車線を変えたり、交差点で曲がって別の道へ入ったりできます。道の端からは出られません。
- **動く場所:** ブラウザ（Chrome）で動きます。Mac では確かめています。Windows でも同じ手順で動くはずですが、まだ試していません（`tools/demo-start.sh` だけは Mac 専用）。
- **会場が東京でも:** 北海道を走っている現在地をスマホへ渡せます。

```
ハンコン・ペダル ─ Chrome（このシミュレータ）─ 開発サーバーの中継（TCP 8788）─ スマホの旅れこ（Debug）
                   ストリートビュー＋OSM の道                                 ナビの案内・車載画面
```

## 準備

### 1. 部品を入れる

Node.js 22 以上を入れておきます（22 で確かめています）。

```sh
git fetch
git switch feat/drive-simulator
cd simulator
npm install
```

### 2. Google の API キー

景色の写真を読むのに、Google の API キーが要ります。キーは `simulator/.env.local` に1行で書きます。`.env.local` は git に載らない設定（`simulator/.gitignore`）なので、コミットされません。キーは人に渡したり、Discord のチャンネルや issue に貼ったりしないでください。

**キーをもらった人（Mac・Linux）:**

```sh
echo "VITE_GOOGLE_MAPS_API_KEY=<もらったキー>" > .env.local
```

**キーをもらった人（Windows の PowerShell）:**

```powershell
Set-Content .env.local "VITE_GOOGLE_MAPS_API_KEY=<もらったキー>" -Encoding ascii
```

PowerShell で `echo ... > .env.local` を使うと、文字コードが UTF-16 になってキーが読めません（画面に「Google の API キーがありません」と出る）。上の `Set-Content` で作るか、メモ帳で UTF-8 として保存してください。

**キーを作る人（旅れこの GCP プロジェクトの管理者）:** キーは旅れこの GCP プロジェクト（`tabireco-app-2608`）で作ります。Map Tiles API（ストリートビューの写真を自前の表示に使うための API）と、写真の有無を調べる Street View の API だけに使え、`http://localhost:5173` からだけ読めるように絞ります。キーの値は画面に出さず、そのまま `.env.local` へ書きます。

```sh
gcloud services enable tile.googleapis.com street-view-image-backend.googleapis.com apikeys.googleapis.com --configuration=tabireco
gcloud services api-keys create --display-name=tabireco-simulator \
  --api-target=service=tile.googleapis.com \
  --api-target=service=street-view-image-backend.googleapis.com \
  --allowed-referrers='http://localhost:5173/*' \
  --configuration=tabireco --format=none
KEY_NAME=$(gcloud services api-keys list --configuration=tabireco \
  --filter='displayName=tabireco-simulator' --format='value(name)')
echo "VITE_GOOGLE_MAPS_API_KEY=$(gcloud services api-keys get-key-string "$KEY_NAME" \
  --configuration=tabireco --format='value(keyString)')" > .env.local
```

2026-11-05 にこの手順でキーを作りました。

### 3. 起動する

```sh
npm run dev
```

Chrome で **http://localhost:5173** を開きます。キーを localhost に絞っているので、`127.0.0.1` や PC の IP アドレスで開くと写真が読めません。

- Windows で初めて起動すると、ファイアウォールの確認が出ることがあります。スマホとつなぐ口（8788）を開くためです。スマホとつながないなら、キャンセルで構いません。
- `.env.local` を作り直したら、`npm run dev` を止めて（Ctrl+C）起動し直します。

## 走らせ方

### 画面の見方

| 場所 | 出ているもの |
| --- | --- |
| 左上 | 走っている道、目的地、目的地までの直線の距離 |
| 真ん中の上 | 今いる道の名前と、次の分かれ道までの距離 |
| 右上 | スマホとのつながり、景色の読み込みの状態、読んだ写真のタイルの枚数（費用の目安） |
| 下 | ハンドルの切れ具合（丸の中の印）、ブレーキとアクセルの踏み具合（棒）、速さ |
| 左下・右下 | Google の表記と「この画像の問題を報告」（規約で必要。隠さない） |

### 道を選んで走る

1. 開くと道を選ぶ画面が出ます。目的地ごとに「ふつうの道」と「景色のいい道（旅れこのおすすめ）」が並ぶので、ボタンを押すか、ボタンの頭の数字のキーで選びます。URL に `?route=onuma-lake&kind=scenic`（ふつうの道は `kind=normal`）のように付けると、選ぶ画面を飛ばして走り出します。
2. アクセル（W か ↑、ハンコンならペダル）で進み、ブレーキ（S か ↓ かスペース）で止まります。
3. 道幅の中を自由に走れます。ハンドルを切ると車の向きが変わり、向いている方へ進みます。分かれ道では、速さを落として、行きたい道の方へハンドルを切って入ります。道の端に当たると、端に沿って滑りながら速さが落ち、向きが道なりへ戻ります。道の外（駐車場や空き地）へは出られません。道の真ん中から離れるほど、まわりの建物がゆがんで見えます（写真に奥行きの情報がないため）。
4. 行き止まりでは止まります。止まっているときに U キー（または調整で決めたボタン）で向きを変えます。
5. 最初からやり直すときは Backspace、別の道を選ぶときは M です。

| 道 | `route=` | 旅れこの目的地 | 距離（最短） | ストリートビューのある地点 |
| --- | --- | --- | --- | --- |
| 万代町 → 函館駅（ともえ大橋）| `hakodate-tomoe` | 函館駅 | 約2km | 見比べた6地点はすべてあり |
| 大沼公園駅 → 東大沼 | `onuma-lake` | 東大沼 | 約7km | 見比べた7地点はすべてあり |

- **出発点と向き:** 旅れこの経路サーバーで引いた経路の最初の点です（`src/routes.ts`）。
- **ストリートビューのある地点の割合:** 2026-11-05 に、その経路を 250m おきに Google の写真の有無（メタデータ）で調べた結果です。
- **試し走りは短めに:** 写真のタイルは読んだ枚数でお金がかかります（「規約と費用」を参照）。右上の枚数を見ながら走ってください。

### ふつうの道と、景色のいい道を走り比べる

同じ出発地と目的地で、2本の道を走り比べられます。

- **景色のいい道:** 旅れこの景観ルート推薦が出した案のうち「景観と時間のバランス」の道です（無ければ、寄り道のある案のうち点数の高い道）。その案がふつうの道とほとんど同じ道のときは、海や湖の区間が長い別の案を選んでいます。
- **ふつうの道:** Google の Routes API（Google マップの案内と同じ経路計算）の道です。今のデータは、API キーで Routes API が許可されていないため、旅れこの経路サーバーの「寄り道なしの最短」で代用しています。画面には「寄り道なしの最短」と出ます。
- **左下の枠:** 2本の道の地図（走っている方が太い線）と、道の始まりから終わりまでの景色を色で表した帯が出ます。帯の白い印が今いる所です。景色は地図からの推定で、実際に見えるかは確かめていません。
- **上の案内:** 次の分かれ道で、選んだ道がどちらへ曲がるかが出ます。道から 40m 以上外れると、戻るよう知らせます。
- **T キー:** 同じ出発点から、もう一方の道を走り直します。

- **1か所だけ見る:** URL に `&at=12000&look=-55` を足すと、道の始まりから 12km の地点に、道の向きから左へ 55 度向いて止まります（右は `look=55`）。先の写真は読みません。推定した景色が実際に見えるかを確かめるのに使います。

- **短い道:** ブースで数分で走り比べられるよう、短い道を入れています。次の2本は、おすすめの道の景色をストリートビューで見て確かめました（2026-11-11）。稚内駅 → ノシャップ岬と留萌駅 → 黄金岬は候補で、景色の確認が済んでいません。
  - 万代町 → 函館駅：ふつうの道は国道5号の市街地（2.3km・約3分）、おすすめの道は函館港の上を渡るともえ大橋（3.2km・約5分）。橋の上から海と函館山が見えます。
  - 大沼公園駅 → 東大沼：ふつうの道は林の中の近道（6.5km・約8分）、おすすめの道は大沼の湖畔を回る道道338号（11.6km・約13分）。紅葉の林と湖が続きます。

2本の道のデータは `tools/fetch_compare.py` で取り直します。旅れこの推薦は取るたびに少し変わることがあります。

```sh
VALHALLA_URL=https://… ROUTING_TOKEN=… python3 simulator/tools/fetch_compare.py
# Google の経路を使うとき（Routes API を有効にしたキー）
GOOGLE_ROUTES_API_KEY=… VALHALLA_URL=https://… ROUTING_TOKEN=… python3 simulator/tools/fetch_compare.py
```

`public/compare/<道の id>.json`（2本の道の形・距離・時間・景色の内訳）と、2本の道の両方を覆う `public/roads/<道の id>.json` を書きます。Google の経路を取る部分は、キーが無いため動かして確かめていません。

## ハンコン（G29）をつなぐ

### つなぐ前に

| 確かめること | どうする |
| --- | --- |
| 切り替えスイッチ | ハンドルの中の枠の上（回転数ランプの裏）にある切り替えスイッチを **PS4** にする。PS3 だと古い機種として見え、クラッチなどが効かない |
| 挿す口 | G29 の USB を、PC の USB の口に**直接**挿す。ハブや変換アダプタを通すと読めないことがある |
| 電源 | G29 の電源の線もつなぐ。つなぐとハンドルが左右に回って止まる（自己調整） |
| ペダル | ペダルの線をハンドルの裏につなぐ |
| Windows | Logicool G HUB を入れておく。ハンドルの手応え（中心に戻る力）は G HUB 側で出る見込み（未確認） |
| Mac | macOS Ventura 以降で読める。ハンドルの手応えは効かないので、手でまっすぐに戻す |

### 初めての PC では調整する

Chrome には、ハンコンは「ゲームパッド」として見えます（Gamepad API）。G29 は OS や切り替えスイッチで軸の番号と向きが変わるので、決め打ちにせず、その場で動かしてもらって覚えます。

1. シミュレータを開いてから、**G29 のボタンをどれか1回押します。** Chrome は、ボタンを押すまでハンコンを見せません。
2. 押すと、**調整画面が自動で開きます**（開かなければ C キー）。
3. 7段階で答えます。各段で、言われたとおりに動かして**押さえたまま Enter**（か「次へ」）を押します。

| 段 | すること | 覚えるもの |
| --- | --- | --- |
| 1 | アクセルとブレーキを一度ずつ踏んで離し、ハンドルをまっすぐにして手と足を離す | 何もしていないときの各軸の値 |
| 2 | ハンドルを左いっぱいまで回して押さえる | ハンドルの軸と、左いっぱいの値 |
| 3 | ハンドルを右いっぱいまで回して押さえる | 右いっぱいの値 |
| 4 | アクセルを奥まで踏んで押さえる | アクセルの軸と、踏み切ったときの値 |
| 5 | ブレーキを奥まで踏んで押さえる | ブレーキの軸と、踏み切ったときの値 |
| 6 | U ターンに使うボタンを押す（使わないなら Enter） | ボタンの番号 |
| 7 | 出発点へ戻るボタンを押す（使わないなら Enter） | ボタンの番号 |

調整画面には、軸ごとの今の値がバーで出ます。動かしたときに大きく変わる番号が、その操作の軸です。

覚えた割り当ては、その PC の Chrome（localStorage）に、ハンコンの名前ごとに残ります。次からはボタンを1回押すだけで使えます。道を選ぶ画面の下に「ハンコン：…（調整済み）」と出ていれば、割り当てが読めています。

### うまく動かないとき

| こうなったら | 直し方 |
| --- | --- |
| 道を選ぶ画面に「ハンコンが見えません」と出る | G29 のボタンを1回押す。それでも出なければ、USB を挿し直して Chrome を再読み込みする |
| ハンドルを回すと逆に曲がる | C キーで調整し直す |
| ペダルを離しているのに進む・ブレーキがかかったまま | C キーで調整し直す。段1で、ペダルを一度ずつ踏んでから離すのを忘れない（Chrome は、一度動かすまでペダルの値を 0 と見せることがある） |
| 「動きが読み取れませんでした」と出る | いっぱいまで動かして、押さえたまま Enter を押す（0.3 より大きく動いた軸だけを拾う） |
| 調整した割り当てを消したい | Chrome の開発者ツールの Application → Local Storage → `http://localhost:5173` から消す。C キーで調整し直せば上書きされる |

### 運転の感触を直すときに触るところ

| 直したいこと | 場所 |
| --- | --- |
| 加速の強さ・ブレーキの効き・アクセルを離したときの減り方・最高速度（今は時速 60km、ブレーキは実車の約3倍） | `src/vehicle.ts` の `CAR` |
| ペダルの踏みはじめの遊び（今は 3%）、ハンドルの値の出し方 | `src/calibration.ts` の `pedalValue`・`steerValue` |
| ハンコンの読み取り、ボタン、キーボードとの切り替え、キーボードのハンドルの切れる速さ | `src/input.ts` |
| 調整の段と文言 | `src/calibrationView.ts` |
| ハンドルの効き（前輪の切れ角、速いときの曲がりにくさ） | `src/vehicle.ts` の `CAR`（`maxSteerDegrees`・`maxLateralAcceleration`）と `yawRate` |
| 道幅（道の種類ごと）、道の端の収め方 | `src/roads.ts` の `halfWidth`・`keepOnRoad` |
| 道の端に当たったときの速さの落ち方と、向きの戻り方 | `src/main.ts` の `drive` |
| 視点の高さと角度、画面の表示 | `src/main.ts` |

直したら `npm test` と `npm run typecheck` を流してください。ハンコンがなくても、軸の読み取りは `test/calibration.test.ts` で確かめられます。

## 道路のデータ

`public/roads/<道>.json` は、旅れこの経路から 300m 以内の車道を OSM から取ったものです（© OpenStreetMap contributors、ODbL）。私道・農道・歩道は入れていません。取り直すときは次のとおりです。

```sh
VALHALLA_URL=https://… ROUTING_TOKEN=… python3 simulator/tools/fetch_roads.py [道の id …]
```

## スマホとつなぐ

スマホには Debug ビルドの旅れこを入れます。Debug ビルドにだけ、位置を受け取る口（`SimulatorLinkReceiver`）が入っています。

USB かワイヤレスデバッグで PC とつないだスマホは、次のとおりです。

```sh
adb reverse tcp:8788 tcp:8788
adb shell am broadcast -n com.tabireco.app/com.theacar.android.debug.SimulatorLinkReceiver -a com.theacar.debug.SIMULATOR
```

「シミュレータにつながりました」と出て、シミュレータの右上が「スマホ 1台に位置を送っています」になれば、つながっています。

- **スマホが車載機に USB でつながっているとき:** ワイヤレスデバッグ（Android 11 以降）で `adb` をつなぐか、同じ Wi-Fi で PC の IP アドレスを指定します（`--es host 192.168.0.10`）。会場の Wi-Fi は、端末どうしがつながれない設定のことがあります。
- **アプリが落ちたり開き直されたりしたとき:** 前のつなぎ先へ自動でつなぎ直します（10秒ほど）。
- **止めて実機の測位へ戻す:** `--ez stop true` を付けて同じ放送を送ります。自動のつなぎ直しも止まります。
- **目的地は自動で入る:** シミュレータで道を選ぶと、出発点の位置のあとにその道の目的地（`routes.ts` の destination）が届き、旅れこが前の案内を止めてルートを引き、そのまま案内を始めます（車の画面と同じ、景観の指定なしのルート）。スマホで検索して打つ必要はありません。

### デモの日：1回で起動する

確認用の旅れこを入れたスマホを USB でつなぎ、次を打ちます。

```sh
simulator/tools/demo-start.sh
```

中継と開発サーバーを開き、USB の転送を張り、スマホの Android Auto のヘッドユニットサーバーを起動して DHU を開き、旅れこをシミュレータとつなぎ、Chrome でシミュレータを開きます。DHU が閉じたり線が抜けたりしたら、つなぎ直して開き直します。Ctrl+C で止めます。アプリは `APP=com.tabireco.app` のように変えられます（既定は `com.tabireco.app.dev`）。Android Auto の開発者モードは先に有効にしておいてください。

### スマホがネットにつながっていないとき

会場の Wi-Fi に入れないときなどは、USB の線で Mac のネットを使わせます（2026-11-06 に moto g50 で確かめた）。

```sh
VALHALLA_URL=https://<経路サーバー> node simulator/tools/phone-proxy.mjs   # Mac で中継を開く（8790）
adb reverse tcp:8790 tcp:8790
```

旅れこの Debug ビルドは、接続先を中継に向けて作ります。

```sh
ORG_GRADLE_PROJECT_VALHALLA_URL=http://127.0.0.1:8790/routing \
ORG_GRADLE_PROJECT_MAP_STYLE_URL=http://127.0.0.1:8790/ofm/styles/liberty \
ORG_GRADLE_PROJECT_ROUTING_TOKEN=… ./gradlew :androidApp:assembleDebug
```

- 中継は、地図の設定ファイルの中の配信元のアドレスも中継を通るように書き換えます。
- 接続先が `http://127.0.0.1` のときだけ、地図の部品（MapLibre）を「ネットにつながっている」扱いにします（`SimulatorLinkStarter`）。そうしないと、端末がつながっていないと見て地図を取りに行きません。
- **別の PC で作った旅れこが入っている端末:** 署名の鍵が違うと上書きできません。`-PDEBUG_APP_ID_SUFFIX=.dev` を付けて作ると、`com.tabireco.app.dev` として並べて入ります（放送の宛先も `com.tabireco.app.dev/…` に変わる）。

## 規約と費用

- **保存しない:** ストリートビューの写真は、走るたびに Google から読み込んで表示します。写真を保存・一括ダウンロードしてはいけません（Google Maps Platform 規約 3.2.3(a)）。保存してよいのは写真の ID だけです（Map Tiles API のポリシー）。
- **表記:** 画面の左下に「Google Maps」と写真ごとの出典、右下に「この画像の問題を報告」のリンクを出します（Map Tiles API のポリシー）。消したり隠したりしません。正式なロゴの画像はまだ入れておらず、文字で出しています（要対応）。
- **宣伝の動画に使わない:** ストリートビューの画像は、宣伝用の動画に入れてはいけません（同ポリシー）。ピッチの動画にシミュレータの画面を入れないでください。
- **地図を混ぜない:** ストリートビューと Google 以外の地図を同じ画面に出してはいけません（規約 3.2.3(e)）。シミュレータには地図を出さず、OSM の道は車を道に乗せるためだけに使います。ナビの地図はスマホの画面に出します。この使い方が規約の上で問題ないかは要確認です。
- **費用:** 写真のタイル（512×512）1枚ごとに数えられます。月10万枚まで無料、その先は1,000枚で約2ドルです（2026-11 の料金表）。画面は縦に3つに割り、正面の窓と、左右 60 度を向く窓（どれも横 60 度。合わせて 180 度がつながり、外の端が真横）を並べます。そのため前方の 5〜6 列 × 2 段を、写真約 10m おきに読みます（左右の窓を足す前は 3〜4 列。枚数は測り直していません）。15〜20m おきだったときは 1km あたり約 350 枚（2026-11-05 に黄金道路で測定）だったので、今はその約2倍、時速 60km で1時間走ると約4万枚の見込みです（測り直していません）。細かく読むのは、写真から離れるほど植え込みや木が地面に沿って伸びて見えるためです。写真の ID は 3 秒に1回まとめて聞きます。
- **1時間の使い回し:** 写真のタイルは「1時間は使い回してよい」と指定されています（`Cache-Control: max-age=3600`）。Google とのセッションをブラウザに残して使い回すので、1時間以内に同じ道を走ると、ブラウザに残った写真が使われます。残すのはセッションの文字列だけで、写真をディスクに保存することはしません（規約で不可）。画面の右上に、読み込んだタイルの枚数を出しています。
