# Wi-Fiでの書き込み手順（OTA）

`firmware/car_v3_ble` は、内張りを閉めたままノートPCから書き込める。

**v3 では Wi-Fi は常時立っていない。** 起動時は BLE だけで待ち受け、`o` を送られたときに限って
Wi-Fi と OTA を 5 分だけ立て、時間が来ると自分で切る。窓の操作とログはアプリが BLE で行うので、
この手順はファームウェアを更新するときだけ使う。

アプリからの操作は[窓の操作](../../../docs/window-control.md)を参照。

## 1. v2 から v3 への更新は、一度だけ USB

**パーティションの設定を変えるので、この1回は OTA では更新できない。**

1. `secrets.example.h` を同じフォルダに `secrets.h` としてコピーし、テザリングの名前とパスワードを書く。`secrets.h` は `.gitignore` に入れてあるのでリポジトリには入らない。`.ino` 側は書き換えない
2. キーOFF、DC-DC の白（OUT+）をブレッドボードから抜く
3. Arduino IDE で ツール → **Partition Scheme** → **Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)**
   - 既定の設定ではアプリ領域が 1,310,720 バイトで、BLE と Wi-Fi と OTA を入れると入らない（実測 1,762,419 バイト = 134%）
   - **「Huge APP」は OTA 用の領域が無いので選んではいけない**
4. USB でつないで書き込み（ボード：ESP32 Wrover Module、Upload Speed 115200）
5. シリアルモニタ（115200）で `i` を送り、`BLE: 待ち受け中` と `Wi-Fi: 停止中` を確認
6. USB を抜き、DC-DC の白を戻してキーON

**以降の v3 同士の更新は OTA でできる。** ただし毎回 Partition Scheme を Minimal SPIFFS のままに
しておくこと。Arduino IDE はボードごとに設定を覚えるが、戻ると入らなくなる。

## 2. 機器だけを確かめる（アプリを使わずに）

nRF Connect のような汎用の BLE アプリでつながる。

| 口 | UUID |
|---|---|
| サービス | `6e6b1f00-5f3a-4b7c-9d21-8c4f1a2b3c01` |
| コマンド（write） | `6e6b1f01-5f3a-4b7c-9d21-8c4f1a2b3c01` |
| ログ（notify） | `6e6b1f02-5f3a-4b7c-9d21-8c4f1a2b3c01` |

コマンドの口へ1バイト書く。`i` は情報を返すだけでリレーを動かさないので、送信の経路を無害に確かめられる。

| 入力 | 16進 | 動き |
|---|---|---|
| `i` | `69` | バージョン・BLE・Wi-Fi・センサーの状態 |
| `s` | `73` | 停止 |
| `u` | `75` | 上げ 0.5秒 |
| `d` | `64` | 下げ 0.5秒 |
| `o` | `6f` | Wi-Fi と OTA を 5 分だけ立てる |

ログの口の notify を有効にすると、`ガス 204.4kΩ 普段比 -0% 湿度 32.0%` が1秒ごとに流れてくる。
起動から 5 分は `(暖機中)` が付き、においの検知はしない。

## 3. OTA を立てる

`o` を送る。送り先は BLE（上の表）か、USB のシリアルモニタ。

```
OTA受付を開始しました（5 分で自動的に切ります）
Wi-Fi: 〇〇 に接続 / IP 172.20.10.7
```

5 分で切れる。切れたらもう一度 `o` を送れば立ち直る。書き込み中はタイマーで切られない。

テザリングにつながらないと、ESP32 は自分のアクセスポイント `stepwgn-window`（パスワード `window2026`、IP `192.168.4.1`）を出す。

### iPhoneテザリングの注意

**この設定が必要なのは OTA のあいだだけ。** 普段の窓の操作は BLE なので、Wi-Fi を機器に合わせる必要はない。

- ESP32 は 2.4GHz にしかつながらないので、iPhone の「**互換性を優先**」を ON にする
- このとき PC が `192.0.0.2`（ルーター `192.0.0.1`）という特殊なアドレスになり、ESP32 と通信できないことがあった
- 対処：PC の Wi-Fi の IPv4 設定を **手入力** にする
  - IPアドレス `172.20.10.12` ／ サブネットマスク `255.255.255.240` ／ ルーター `172.20.10.1`
  - DNS に `172.20.10.1` を追加
  - **書き込みが終わったら DHCP に戻す**
- ESP32 側は `172.20.10.7` に固定してある（v2.1〜）

OTA のあいだはポート23も開くので、ログを PC から直接見られる。

```sh
nc -v 172.20.10.7 23
```

終了は control + C。**機器は同時に1つの TCP 接続しか保持しない。**

## 4. OTA で書き込む

Arduino IDE のネットワークポート（`stepwgn-window at 172.20.10.7`）は、この接続方法だと一覧に出てこなかった。ターミナルから直接書き込む。

1. `o` を送って OTA を立てる（手順 3）
2. コードを直して `VERSION` を上げる
3. Arduino IDE で **スケッチ → コンパイル済みバイナリをエクスポート**（Partition Scheme は Minimal SPIFFS のまま）
4. ターミナルで書き込む（`-f` はエクスポートされた `.ino.bin` のパスに合わせる）

```sh
python3 ~/Library/Arduino15/packages/esp32/hardware/esp32/*/tools/espota.py \
  -i 172.20.10.7 -I 172.20.10.12 -p 3232 -a window2026 -r \
  -f <スケッチのフォルダ>/build/esp32.esp32.esp32wrover/car_v3_ble.ino.bin
```

5. `Uploading: [====] 100% Done...` が出たら、20秒待って BLE か `nc` でつなぎ直し、`i` でバージョンを確認

- `.bin` の場所が分からないときは `mdfind -name "car_v3_ble.ino.bin"`（Windows なら `dir /s car_v3_ble.ino.bin`）
- Arduino IDE から書き込んで `Authentication Failed` が出たのは、パスワード入力（全角など）が原因だった。IDE は一度入れたパスワードを覚えてしまうので、再入力したいときは IDE を再起動する
- 書き込みのあいだ、機器はリレーもセンサーも触らない（`otaRunning` のガード）

## 5. 走行中に開発するとき

- 運転者に操作や画面確認をさせない。窓を動かす前に一声かける
- 高速道路やトンネルでは窓のテストをしない
- 書き込み中にキーをOFFにしない（起動しなくなったら USB で書き直せば戻る）
